# Build230 fixed shared membership cutover components

These source components are dormant and have no standalone live mode. They must be composed into the independently reviewed Root release packet after the exact Build230 source, configuration variants, source review, CI, QA, backup/restore and provider gates are ready. No agent execution or activation is implied by local tests.

`preview-rpc.ts` is compiled once with a literal closure JSON/hash, ephemeral capability and exact host, then exposed by one naturally expiring preview using the existing Root preview lifecycle. It needs the existing main D1 binding only, no Discord token, new secret, persistent Worker or private sidecar. The request has only a fixed plan ID and, for later phases, the original closed control tuple. SQL, arbitrary binds, schema mutation and provider requests are absent from the wire API. Every plan executes exactly one actual `env.DB.batch` with original method/statement/result witnesses. Failed/lost replies stay unknown.

`native-rpc-adapter.cjs` maps exact source-owned local statement plans to those five RPC IDs. It retains statement identities, validates the full SQL/bind plan before any request, permits one ordered sequence, marks dispatch spent before I/O, and never resends. The serialized response is explicitly a qualified transport projection of the remote Native packet; it is not falsely described as an unchanged cross-process object identity. Its parsed original result graph is what the local Native issuer witnesses across awaits.

`owned-operator.cjs` retains the original WeakMap fence ACK in one pinned local module instance across Root's protected successor deployment and original open/OFF-abort. Its three supplied effects must be the frozen, source-qualified Root provider-read/protected-deploy/append-only-receipt functions, not caller booleans. Root's release packet must authenticate with the existing pinned SDK internally, create/bracket the preview, qualify production source/bundle/100% assignment and exact bindings, run the engine, then prove natural expiry and unchanged intended production state. This composition/lifecycle is an explicit outstanding live gate. The engine exposes no credential loader or generic deploy command.

The close-only A configuration restricts new old-family fixed-target producers while Native Eold remains serving, so original callbacks can persist their own ACK/unknown and genuinely owned compensation. S2 atomically rechecks all physical-target custody before fencing. The only admitted historical record is the exact source-original pre-cutoff legacy PUT ACK with no child; everything else holds. S2 uses one temporary source-owned active/nonce/purpose segment for the exact seal INSERT, restores neutral control, preserves the original counters, and changes only to fresh Enew/closed. No triggers are disabled and no DDL occurs.

The successor B uses the same qualified runtime bundle, Enew and full external closure pin. Its actual UUID is bracketed independently; the original closure does not contain a future UUID. B must be `enabled`, or a separately qualified `close-only` OFF abort; both consume the same original ACK and original deadline of at most300 seconds. No unknown fence/deploy/open is retried or repaired from SELECT. A lost ACK/process/deadline leaves the global Native hold pending a separately reviewed recovery procedure.

The hold affects all main Native-backed D1 pages/APIs/cron and ACK writers, not Discord globally. Root must account for other in-flight Native-backed provider work; preserve its unresolved custody honestly. Other eleven beta targets, existing privacy authority and legacy beta epoch guards retain their own behavior. The eight Council overwrites remain held.

The outside expected epoch and closure pin reject pre-cutover/other-epoch restores. A sanctioned later same-epoch restore is an operator responsibility: burn/rotate the outside expected epoch before serving and use fresh reviewed original cutover/recovery authority. Neither the seal nor audit watermark proves exclusion of arbitrary same-epoch replay.

Local checks: pinned Node24 `worker/tests/shared_membership230_cutover_test.cjs` and `tools/shared-member-cutover230/tests/rpc_test.cjs`. No test reads private configuration, provider credentials, subject state or live D1.

The separately source-qualified OFF-only recovery protocol is `privacy-shared-member-recovery230.ts`, with `recovery-preview-rpc.ts`, the closed recovery adapter and `owned-recovery-operator.cjs`. Its original plan binds the observed exact current control tuple (old-serving, new-closed or new-serving), a fresh epoch, the same source/commit/tree/bundle and an original300-second window. Root first deploys that same qualified source with mode close-only and the plan's fresh epoch through the protected ordinary-plan selector. One new exact Native fence consumes the observed tuple; only its NEW original ACK opens the fresh epoch OFF. It preserves every role-debt row and existing closure pin, has no enabled operation, and supplies no role-reuse qualification. A late old epoch/open statement fails after the new CAS. This is a new recovery mandate, not a reconstructed old ACK or a retry of a lost operation.

The protected deployment script accepts only `--shared-member230-mode close-only|enabled`, an optional canonical ordinary `--shared-member230-closure`, or a mutually exclusive `--shared-member230-recovery` with close-only. Main+keep-vars+exact tag/message are mandatory; combining source-tree binding is refused. A emits MODE only, B/OFF-abort closure emits exactly MODE+closure JSON/hash+epoch, recovery emits only MODEclose-only+fresh epoch and preserves old closure pins. The archived checker executes only its own archived pure source parser and closed constants in an isolated VM; no runtime handler, credential or provider code is loaded. These flags do not substitute for Root's actual main/QA/backup/provider gates.

Original module receivers, function descriptors and prototypes are captured before the first await in both owning engines. Provider/deployment/receipt callbacks cannot replace issuer or facts functions later.
